## 封面字段语义（2026-10 实测，勿按字面猜）

抖音 `aweme_detail.video` 节点有多个封面字段，含义不同，取错就会拿到视频随机帧而不是作品展示封面：

| 元数据字段 | 实际内容 | 取用 |
|---|---|---|
| `dynamic_cover` | 作品实际展示封面的大图（无 tplv 原对象，实测 724×966 ~ 1215×1621） | ✅ 最优先 |
| `cover_original_scale` | 作品实际展示封面本体（tplv-dy-360p，实测 360×480） | ✅ 次优 |
| `cover` | 本批样例为展示封面的横裁图（image-cut 模板，实测 440×330） | 仅辅助比对，不自动上传 |
| `origin_cover` | 本批样例为自动截帧（糊帧/黑帧/怪角度），与作品展示封面不同 | 排除自动兜底 |

- 不要用元数据 `width`/`height` 打分选图：与实际下载尺寸不符（如 `dynamic_cover` 元数据 720×720、实下 724×966+），优先级只用来取候选；仍需下载查看实际内容并核对作品 ID。
- 图文(note)作品没有 video 封面可看：展示封面是 `images[0]` 竖版原图（约 1080×1920），其 `url_list` 里 webp 变体在前、jpeg 变体在后，优先取 jpeg 变体。
- note 页不调 aweme/detail，note 元数据从作者作品列表接口 `/aweme/v1/web/aweme/post/` 的同 aweme_id 节点取。
- 图文短链跳 `/share/note/{id}`（非 `/video/{id}`），`resolve_video_id` 已识别并给出图文通道提示。

## 日期与空值

- 发布日期统一为 `YYYY-MM-DD`。
- 字段值为空时从 payload 中省略，不写 `null`。
- 附件字段不能直接写普通 CellValue；脚本会在记录创建/更新后调用 `+record-upload-attachment`。
- 目标表没有的逻辑字段直接跳过。





## 行业判断与单选写入

流程：全文中的主营业务 → 规范行业名 → 实时单选项 → 证据原句 → 写入并核对。
当前工厂实体店、新增情感共鸣型表均有行业单选；其他表是否新增以本次 field-list 为准，不从旧配置推测。
当前已核实选项：门窗、餐饮、服装、五金、瓷砖、纸箱。这是 2026-10-15 快照，不是封闭行业全集。

| 文案事实 | 行业 | 判断原因 |
|---|---|---|
| 我开火锅店，每天备菜到深夜 | 餐饮 | 火锅是餐饮业态，不另建“火锅店” |
| 做女装十年，今天收摊后去吃火锅 | 服装 | 吃饭是生活场景，主营仍是女装 |
| 我们门窗厂选的五金件都能追溯 | 门窗 | 配件服务于门窗主营业务 |
| 我不做餐饮，我是做门窗的 | 门窗 | 不能把被否定的行业当主营 |
| 门窗、餐饮、服装老板都要学沟通 | 待补 | 并列举例没有唯一行业，不按首个词填 |
| 人到中年，要学会与自己和解 | 待补 | 情感主题没有行业事实 |
| 我们厂做纸箱、飞机盒和纸板 | 纸箱 | 产品证据具体，不笼统归“工厂” |

有依据时示例：
```json
{"industry":"餐饮","industry_evidence":"我开火锅店，每天备菜到深夜"}
```
依据必须来自 payload.full_text，不能编造原句。行业数组、多值拼接、未知选项会在写入前被拒绝。
只有先确定行业再归一化同义名称；脚本不会扫描全文见词就分类。新行业缺选项时保留现有选项补充标准名称，再查询确认；不要产生“餐饮/火锅”“实体店”等混合层级值。
无依据时省略 industry，并填写 industry_status=undetermined、industry_reason。不会用空值清除已有行业。

## 运行纠偏与验收

- 封面对应的是“该作品实际展示内容”，不是名字里有 origin、尺寸最大、竖版或带文字就正确。无贴字封面经交叉比对也可验收。
- 下载候选图后查看；核对目标作品 ID、作者、人物和场景。发现纯黑、糊帧、裁切或作品不符，不能靠更换文件名掩盖；尝试下一可靠源，仍无法确认就留空/保留旧图并报告。
- 自动提取 payload 的 cover_verified 默认 false。实际验收后补 true、cover_source（dynamic_cover / cover_original_scale / images[0] / user_supplied）、cover_verification_note。后者注明作品 ID 和对应依据，不可未看图就标记。
- 元数据 width/height 仅是标称值。要报告尺寸时读取下载图片的实际尺寸；不要凭标称宽高判断封面。
- 图文链接先识别 note。当前自动提取器会明确停止并提示作者作品列表通道；手动读取 aweme/post 时必须取同 aweme_id 的节点。图文图片文字属于图文原文，不伪称口播转写。
- 替换附件：下载并核验 → 读旧 token → 上传新图 → 读回确认新 token → 只删之前的旧 token → 再读回确认仅一张正确图。上传失败保留旧图；删除失败报告新旧并存，不报全部完成。
- 按规范作品链接查重；同标题、同尺寸、同文件大小不能单独证明重复。历史短链先解析为作品 ID，再比对目标表；查重报错必须停止，不能当成“没有记录”而新建。删除历史重复记录需有该任务的删除授权。
- 机器转写与行业判断分开：只有原音/字幕或清楚语境支持才校正同音字，不为了套行业而改原文。保留原文证据。
